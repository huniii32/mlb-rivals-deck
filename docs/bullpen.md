# 불펜 배치와 전술

타자 9명·선발 5명에 더해 불펜을 총 7명까지 배치한다. 승리조·추격조·롱릴리프는
각 최대 4명, 마무리는 최대 2명이다. 역할별 상한과 불펜 전체 상한을 함께 적용한다.

| 역할 | 전술 | 이름이 등록된 최소 인원 | 지구력 제외 능력치 보너스 |
|---|---|---:|---:|
| 승리조 | 기본 | 없음 | 0 |
| 승리조 | 적극 | 2 | +2 |
| 승리조 | 분업 | 3 | +4 |
| 추격조 | 기본 | 없음 | 0 |
| 추격조 | 적극 | 2 | +2 |
| 롱릴리프·마무리 | 기본 | 없음 | 0 |

스크린샷의 ‘최소 배치 필요 인원’에 따라 그 이상의 인원도 전술을 적용할 수 있다.
승리조 3명이 적극을 선택하면 +2, 분업을 선택하면 +4다. 빈 슬롯은 인원 조건에
포함하지 않는다. 충족되지 않은 전술 선택은 보관하되 보너스는 0이며 화면에 안내한다.

예: 승리조 3명(분업)·추격조 2명(적극)·롱릴리프 1명·마무리 1명은 총 7명이다.
승리조 각 선수의 변화·구위에 +4, 추격조 각 선수에 +2를 가산하고 나머지는 가산하지 않는다.
앱에서 점수에 사용하는 투수 능력치는 변화·구위이므로 각각 능력치 점수 +9.4, +4.7에 해당한다.
지구력에는 가산하지 않으며 선발·타자·스킬 점수도 변경하지 않는다.

최종 스탯을 수동 입력할 때는 **전술 적용 전 수치**를 입력한다. 전술 보너스는
수동/자동 스탯에 똑같이 한 번만 반영한다. 상세표와 미리보기에서 전술 열을 확인할 수 있다.
스킬 점수는 모든 경우 랭킹대전 기준이며 리그·라이브 매치 전용 효과는 제외한다.

## 저장과 호환성

- 기존 18명 덱은 그대로 읽으며 RP1→승리조, RP2→추격조, RP3→롱릴리프,
  CP1→마무리로 이전한다. 기존 덱의 전술 기본값은 기본/기본이다.
- 역할과 전술은 덱 JSON에 저장하며 파일·공유 링크·랭킹 복원에서도 유지한다.
- 배치를 줄일 때 빈 슬롯부터 제거한다. 등록된 선수를 제외하려면 화면에서 확인을 받는다.
- 추가 투수의 덱코·포훈은 해당 역할의 기존 엑셀 프로필을 재사용하며 선수 자신의
  카드·연도·강화 수치로 평가한다. 불펜 총점은 이름 있는 불펜 전원의 평균×10이다.
- 서로 인원이 다른 덱도 역할과 역할 내 순번으로 비교하며 없는 선수는 빈 칸으로 표시한다.

## 공개 랭킹 DB

기존 DB에는 `named <= 18` 제약이 있다. 19~21명 덱을 공개 랭킹에 등록하기 전
[supabase_mig_bullpen.sql](../scripts/supabase_mig_bullpen.sql)을 Supabase SQL Editor에서
적용해야 한다. 신규 설치용 기본 스키마는 21명까지 허용한다. 운영 DB의 공개 목록은
읽기만 했으며 데이터나 스키마는 변경하지 않았다.

검증: `scripts/verify-bullpen.ts`는 기존 덱 호환, 인원 제한, 최소 인원, 전술 가산,
수동 스탯, 추가 선수 프로필, 점수 평균, 파일·랭킹 왕복 및 랭킹대전 스킬 기준을 검증한다.
