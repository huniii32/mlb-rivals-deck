# 라이벌덱 개발 계획

기록일: 2026-11-19 (한국 시간). 사용자가 논의한 개발 방향과 추가 제안을 정리한 작업 기준 문서다. 아래의 ‘계획’은 구현·배포 완료를 의미하지 않는다.

## 1. 사용자가 정리한 핵심 개발 방향

### 덱관리

1. **선수 능력치와 스킬 내용 수집**
   - 이미지 캡처 및 내용 추출 프로그램을 기반으로 게임 내 자료를 확보한다.
   - 정확한 계산에 필요한 데이터를 검증한 뒤 덱관리와 추천 기능에 반영한다.
2. **각 구단의 IN100 라인업·능력치 수집과 고점 덱 연구**
   - 실제 게임의 상위권 라인업, 선수 카드, 능력치, 스킬 및 적용 조건을 수집한다.
   - 구단별 참고 덱과 선수 교체 후보를 구성하고, 계산상 고점 덱을 연구한다.
3. **덱코칭 AI 구현**
   - 검증된 선수·스킬·확률 데이터와 사용자 덱을 연결해 육성 우선순위를 설명한다.
   - 계산은 기존 엔진이 담당하고 OpenAI API는 근거 설명과 질의응답을 담당한다.

### 편의 기능

1. **스킬 자동변경 프로그램 구현**
   - 목표 스킬·점수·변경권·잠금·사용 상한을 설정해 반복 작업을 줄인다.
   - 매 결과를 확인한 후에만 다음 변경을 실행하고, 목표 달성 시 정지한다.

### 라이벌 시리즈

1. **월별 19/4/5 버프 조합 라인업 추천**
   - 매월 업데이트 공지를 기준 자료에 반영해 목표 버프를 만족하는 여러 라인업을 제시한다.
   - 기존 덱에서 적게 교체하는 조합, 보유 카드 중심 조합, 고정 선수를 유지하는 조합을 비교한다.
   - 19/4/5의 정확한 의미와 현행 버프 규칙은 확인 후 구현한다. [별도 계획](rivals-series-plan.md)에 데이터 요건·월별 갱신·검증 순서를 기록했다.

## 2. 선행 관계와 개발 순서

핵심 순서: **캡처 안정화 → 수집 → 추출·검증 → 계산 정확도 확보 → 덱 분석·추천 → AI 설명**.

| 단계 | 작업 | 완료 판단 기준 |
| --- | --- | --- |
| 1 | 개인용 캡처 도우미 안정화 | 단계별 재캡처·동작 테스트가 가능하고, 누락·실패를 식별해 이어서 수집할 수 있음 |
| 2 | 선수·스킬 자료 수집 및 검수 | 원본 이미지와 추출값이 연결되고, 미확인 항목을 검증 완료 자료와 구분할 수 있음 |
| 3 | 덱 계산 검증 | 기본/최종 능력치와 버프를 중복 계산하지 않고, 확인된 게임 사례와 대조함 |
| 4 | IN100 자료 축적 및 실험 덱 | 구단·시즌·수집일별 자료를 비교하고, 실제 사용 덱과 계산상 고점 덱을 구분함 |
| 5 | 육성 우선순위·자원 소모 분석 | 사용자 덱과 자원 조건에 따른 변경 전후 점수 및 추정 소모량의 근거를 제시함 |
| 6 | 덱코칭 AI | 엔진 결과와 일치하는 설명을 제공하고, 미확인 효과나 실제 승률을 임의로 생성하지 않음 |

스킬 자동변경은 단계 1의 화면 인식·입력 제어 기반을 공유한다. 목표 스킬을 안정적으로 인식할 수 있는 범위부터 별도로 검증하며, AI 코칭 완성을 기다릴 필요는 없다.

선수 보관함·변경 이력·실험 덱 등의 화면 기능은 데이터 수집과 병행할 수 있다. 다만 자동 최적화와 투자 추천의 정확도는 검증된 데이터 범위에 제한된다.

라이벌 시리즈의 버프 조합 탐색은 해당 모드의 카드 목록·버프 규칙이 확보되면 별도로 시작할 수 있다. 전체 스킬 효과 수집과 AI 연결을 모두 마칠 필요는 없다. 정확한 OVR 순위는 별도 보정 규칙 검증 후 제공한다.

## 3. 데이터 수집 범위

### 선수와 스킬의 기준 자료

- 선수 식별: 이름, 카드 종류, 구단, 연도, 포지션, WBC 국가 등 판정에 필요한 항목.
- 선수 능력치: 기본값과 최종 표시값을 구분하고, 강화·초월·훈련·포지션훈련 등의 적용 상태를 함께 기록.
- 스킬: 이름, 종류, 게임의 실제 레벨 표기, 레벨별 효과, 발동 조건, 적용 대상, 지속 범위.
- 상시 효과와 해당 선수 등판·특정 상황에서만 적용되는 효과를 구분.
- 원본 이미지, 화면 종류, 수집일, 적용 패치 버전, 추출값, 검수 상태를 함께 보관.
- 공식 변경권 확률과 육성 비용은 별도 출처를 관리. 사용자 보유 자원은 직접 입력하거나 별도의 화면 인식 기능으로 확보.

**스킬도감 수집만으로 사용자의 보유 선수·육성 상태·변경권 수량까지 확보되는 것은 아니다.** 선수 상세 화면과 사용자 자원 입력을 별도 작업으로 다룬다.

수집 중 확인할 데이터 공백:

- 포지션훈련 21~26 전체 증가량과 선호 구단 적용 조건.
- 블랙 S3 등 실제 확인되지 않은 레벨별 스킬 효과. S~S4를 일괄 추정하지 않고 해당 카드에서 지원하는 레벨부터 확인.
- 리더 영향력의 전체 조건과 수치.
- 상대 선수에 따라 달라지는 스킬 조건. 필요한 상대 정보가 없으면 조건별 비교로 제시하고 자동 확정하지 않음.

### IN100 자료

- 시즌, 순위, 구단, 수집일과 적용 패치 버전을 기록.
- 선수별 카드·배치·능력치·스킬·육성 상태 및 확인 가능한 덱스코어·전술·버프를 연결.
- 화면에 보이지 않는 값은 미확인으로 보관. 다른 화면에서 얻은 자료를 합칠 때 동일 선수·동일 시점인지 검증.
- 실제 상위권에서 사용된 덱은 ‘실전 참고 덱’, 계산 엔진으로 탐색한 덱은 ‘계산상 고점 덱’으로 구분.
- 인기·사용률을 최적 조합 또는 실제 승률의 증거로 단정하지 않음.
- 사이트 공개 등록 덱 통계와 실제 게임 IN100 통계를 혼합하지 않음. 모든 통계에 표본 수·집계일·출처를 표시.

## 4. 캡처·자동변경 도우미

개인용 프로그램 작업 위치: `/workspace/private-rivals-tools`. 공개 웹 저장소 및 배포 산출물에 프로그램이나 개인 설정을 포함하지 않는다.

### 우선 검증할 캡처 편의 기능

- 단계별 새로 캡처, 위치 조정, 동작 테스트, 이전 단계 이동.
- 게임에서 직접 화면을 바꾼 뒤 현재 단계의 캡처를 갱신하는 흐름.
- 현재 화면이 목록·설명창·선택창 중 무엇인지 확인.
- 게임창 크기·배율·모니터·권한 등 실행 환경과 좌표 프로필의 일치 여부 확인.
- 마지막 완료 항목부터 이어서 수집, 누락 항목만 재수집, 중복 구분.
- 원본 이미지와 추출 내용을 나란히 검수하고 수정.
- 프로그램 업데이트 시 기존 좌표·설정·수집 결과 유지.

과거에 발생했던 창 활성화·마우스 이동 실패·전체화면/다중 모니터 문제를 실제 실행 환경에서 검증해야 한다. 웹의 로컬 테스트 통과를 사용자 PC의 자동 조작 성공으로 간주하지 않는다.

### 스킬 자동변경의 예정 동작

- 필수 스킬, 허용 조합, 최소 점수, 레벨 등 목표 설정.
- 변경권 종류, 첫 줄 잠금, 최대 사용 횟수 설정.
- 변경 후 결과를 캡처·식별하고 기록한 다음 다음 변경 여부를 판단.
- 목표 달성 시 정지하고 결과 이미지 저장.
- 인식 실패, 예상 화면 불일치, 다른 창 활성화 시 일시 정지. 재개 전 화면 확인.
- 긴급 중지와 진행 상태 표시.
- 실제 사용 횟수·결과와 웹 시뮬레이터의 가상 결과를 분리 기록.

실제 변경권이 소모되는 작업은 목표·상한·현재 화면을 사용자가 확인하고 시작하는 흐름으로 구성한다.

## 5. 추가 편의 기능 후보

다음은 논의 중 제안된 후보이며 모두 확정된 구현 범위는 아니다. 우선순위는 현재 추천 순서다.

| 우선순위 | 기능 | 구현 방향 |
| --- | --- | --- |
| 최우선 | 스크린샷 선수 등록·갱신 | 선수 상세 화면에서 항목을 추출하고 사용자 확인 후 등록 |
| 최우선 | 이미지 일괄 처리 | 폴더의 이미지를 선수별로 묶고 중복·누락·인식 실패 위주로 검수 |
| 최우선 | 변경점만 반영 | 기존 선수와 새 캡처를 연결해 달라진 강화·능력치·스킬만 선택 적용 |
| 높음 | 변경 이력·되돌리기 | 변경 전 덱과 선수를 보관하고 복원. 가져오기 전에도 미리보기 제공 |
| 높음 | 선수 보관함 | 편성하지 않은 선수와 동일 선수의 다른 카드·스킬 세팅 보관 |
| 높음 | 실험 덱·가상 교체 | 현재 덱을 복사해 선수·스킬·육성 변경을 시험. 원본은 명시적 적용 전 유지 |
| 높음 | 덱 설정 최적화 | 확인된 규칙으로 덱스코어 선택·연대·불펜 전술을 탐색하고 적용 전 비교 |
| 높음 | 육성 목표·할 일 목록 | 선수별 현재 상태·목표·자원·완료 여부를 기록하고 재캡처로 갱신 |
| 높음 | 조작 프로필 재사용 | 게임창 환경별 좌표를 저장하고 실행 전 테스트 |
| 중간 | 덱 공유 이미지 | 경기장 배치·주요 스킬·점수를 커뮤니티용 이미지로 출력 |
| 중간 | 기기 간 동기화 | PC·모바일에서 덱과 육성 목표를 이어서 확인. 인증 방식은 별도 설계 |
| 중간 | 등록 덱 사용률 | 구단·포지션·카드·스킬별 집계. 표본이 부족한 경우 순위·상위 %를 과장하지 않음 |
| 데이터 확보 후 | 선수 검색 자동 입력 | 검증된 선수·카드 정보를 검색해 기본값을 채우고 육성값만 추가 입력 |

가져오기에서는 인식 실패를 0이나 빈칸으로 덮어쓰지 않는다. 원본을 보존하고 불확실한 항목만 사용자에게 확인받는다. 보관함 선수는 실제 편성 전에는 라인업 점수·효과에 포함하지 않는다.

## 6. 라이벌덱의 차별화 방향

- **내 덱 기준 다음 투자:** 현재 상태와 대안의 선수·덱 점수 차이, 보유 자원 내 목표 달성 추정 확률을 연결한다.
- **계산 근거 공개:** WBC 국가 인원, 연대 적용 대상, 포지션훈련, 상시/등판 효과 등 적용 이유와 제외 이유를 선수별로 보여준다.
- **교체의 덱 전체 영향:** 카드 개인 점수 외에 덱스코어·국가 조건·팀 버프·불펜 전술까지 다시 계산한다.
- **추천 후 실행과 확인:** 코칭 결과를 육성 목표에 저장하고 게임 작업 후 재캡처해 변화와 목표 달성을 확인한다.
- 기존 경기장 포지션 배치를 유지하며, ‘내 덱 진단’과 선수별 ‘교체해 보기’로 연결한다. 새 기능 때문에 기존 화면을 다시 전면 개편하는 것은 현재 확정 범위가 아니다.

숫자는 사이트의 산정 기준 점수이며 실제 승률을 의미하지 않는다. ‘공식 확률 기준 희귀도’와 ‘공개 등록 덱 기준 순위’ 역시 별도로 표시한다.

AI의 서버 연결·비용·캐시 설계는 [덱코칭 계획](deck-coach-plan.md)을 따른다. OpenAI API를 실제 연결하거나 비용을 발생시키는 단계는 아직 진행하지 않았다.

| 선수 화면 자동 등록·갱신, IN100 수집 체계, 고점 덱 탐색 | 후속 개발 계획 |
| 덱코칭 AI | 설계 단계. 실제 API 연결·과금 없음 |
| 스킬 자동변경 프로그램 | 핵심 개발 방향으로 기록. 실제 조작·소모 검증까지 완료됐다고 간주하지 않음 |

웹 개발 브랜치: `feat/nov18-skills-deck-update`, 검토용 [Draft PR #11](https://github.com/huniii32/mlb-rivals-deck/pull/11). 현재 메인에 바로 반영하지 않고 개발 브랜치에서 시험하는 방침을 유지한다.

브랜치 미리보기는 운영 DB 연결을 끈 상태다. 운영 데이터 변경, 종료된 이벤트 추첨 변경, 실제 쪽지 발송은 이 계획 기록에 포함되지 않는다.

## 8. 다음 작업 시작점

1. 개인용 수집 프로그램의 현재 구현 상태와 사용자 PC 실행 환경을 확인한다.
2. 단계별 재캡처·클릭 테스트·중지·재개를 실제 화면에서 검증한다.
3. 스킬 한 종류의 지원 레벨 전체와 선수 한 명의 상세 화면을 끝까지 수집하는 작은 단위부터 확인한다.
4. 원본 이미지 → 추출값 → 검수 → 덱 계산의 연결 형식을 확정한다.
5. 범위를 전체 스킬·선수 자료로 넓힌 후 IN100 수집과 추천 개발로 진행한다.

참고 사이트: [컴투스 프로야구 V26 덱 매니저](https://deck-manager.vercel.app/). 게스트로 선수 보관함·데이터센터·실험 덱 흐름을 확인했으며, 기능 구성을 참고한다. V26의 카드 체계·가중치·수치를 라이벌 계산 규칙으로 그대로 사용하지 않는다.
