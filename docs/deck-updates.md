# 덱 저장·랭킹·자동 계산 변경

## 사용 방법

- 이름 없는 덱은 작성 중인 임시 덱이다. 이름을 정하고 **덱 저장**을 눌러야 이 기기에 보관된다.
- 새 덱은 첫 저장 시 **공개 랭킹에도 연결**을 선택하면 비밀번호(숫자 4자리)를 정한다. 선택을 해제하면 이름만 입력해 이 기기에 저장할 수 있다. 이미 연결된 덱은 이 옵션 없이 자동 반영을 유지한다. 이후 수정은 같은 랭킹 행에 즉시 반영한다. 전송 중 추가 수정은 직전 요청이 끝나면 최신 내용으로 반영한다.
- 다른 기기에 최신 덱이 이미 있으면 **같은 이름·기존 비밀번호로 덱 저장**한다. 서버의 기존 글을 최신 내용으로 갱신하고 해당 기기를 같은 글에 연결한다. 앞뒤/연속 공백과 영문 대소문자 차이는 같은 이름으로 처리한다. 비밀번호가 틀리면 기존 글을 변경하거나 새 글을 추가하지 않는다.
- 다른 기기에서 **덱랭킹 → 내 덱의 가져오기 → 비밀번호**로 관리 권한을 연결한다. 기기마다 다른 수정 토큰을 발급하므로 휴대폰과 노트북의 권한이 함께 유지된다.
- 공개 랭킹의 선수 구성·점수는 계속 공개된다. 비밀번호는 원래 랭킹 행을 수정하는 관리 권한을 보호한다. 공유 링크는 복사본만 전달한다.
- 여러 기기에서 서로 다른 내용을 수정하면 마지막으로 서버에 도착한 덱이 반영된다. 다른 기기의 열려 있는 편집 내용을 자동으로 병합하지 않는다.

## 강화·훈련·덱스코어

최종 능력치를 직접 입력했던 선수도 강화·초월·훈련·카드·덱코·연도 조건 변경에 따른
자동 합계 차이를 기존 최종값에 반영한다. 직접 입력값과 자동 합계의 보정 차이는 보존한다.
최종값을 지우거나 **최종값을 자동 합계로 전환**을 누르면 전체 자동 합계를 사용한다.
훈련재분배의 무작위 결과는 게임에서 확인한 새 훈련 수치를 입력해야 한다.

점수 규칙에 연결된 덱스코어 선택 90개에 대해 조건을 충족하는 선수를 구성하여
정확한 가산값, 수동 최종값 반영, 선택 해제 시 복원을 검증한다.
규칙에서 사용하는 `라이브/시즌` 카드가 선택 목록에 없어 적용할 수 없던
스페셜 380/560 좌, 팀 280/375/460 좌 조건을 선택 가능하게 수정했다.
라이브/시즌의 강화·초월 조견표는 기존 자료에 없으므로 해당 레벨의 자동 가산은
제공하지 않으며 화면에 표 누락을 표시한다. 확인되지 않은 육성 수치는 추가하지 않았다.

팀 330/345는 원본 규칙에 평가 대상 능력치 가산이 없어 선택만 유지하며 이를 화면에 표시한다.
스페셜 615·645는 **좌=타자 / 우=투수** 중 하나와 기준 연도를 함께 선택한다.
- 615: 해당 연대 타자의 정확·선구 +1 또는 투수의 변화 +1.
- 645: 해당 연대 타자의 파워 +1 또는 투수의 구위 +1.
- 사용자가 제공한 게임 화면의 투수 615 제구 +1, 645 수비 +1은 평가 항목이 아니므로 점수에 더하지 않는다.
- 기준 2020은 2020~2029를 포함하며 2019·2030은 제외한다. 두 임계값의 대상은 독립적으로 선택한다.
- 이전 저장본의 연도만으로는 대상을 추정하지 않는다. 미선택 또는 양쪽 선택 상태는 미적용이며 설정에서 대상을 다시 선택해야 한다.
- 직접 입력한 최종 능력치는 불러오기만으로 임의 수정하지 않는다. 기존 잘못된 자동 가산을 포함해 직접 저장한 값이라면 대상을 설정한 뒤 게임 능력치와 맞춰야 한다.
- 680의 연도 조건은 이번 수정 대상이 아니며 기존 규칙을 유지한다.

중계 포지션훈련은 기존 조견표를 유지한다. 단계 입력 → 역할별 조회 → 적용 능력치 → 선수 점수 → 불펜 평균/덱 총점 경로를 검증했다.
승리조·추격조·롱릴리프·마무리와 추가 슬롯(31~33), 자동값 및 직접 입력 최종값에서 정상 반영된다.
편집 화면의 단계 입력 아래에 현재 변화·구위 가산량을 표시한다. 이 검증은 프로그램 내 반영 경로에 대한 것이며,
조견표 전체가 최신 게임 수치와 같은지 확인한 것은 아니다.

## 운영 DB 적용

프런트엔드 배포 전에 Supabase SQL Editor에서 관리자 권한으로 순서대로 실행한다.
기존 `supabase_mig_owner_codes.sql`이 적용된 DB를 전제로 한다.
레거시 `supabase_mig_ranking_upsert.sql`도 사용할 경우 비밀번호 마이그레이션보다 먼저
적용한다. 비밀번호 전환 뒤 구 등록 RPC의 실행 권한을 다시 열지 않는다.

1. `scripts/supabase_mig_bullpen.sql`
2. `scripts/supabase_mig_deck_passwords.sql` — 숫자 4자리 검증·동일 이름 갱신·이름 고유 인덱스 포함. 이전 파일을 적용했어도 현재 파일 전체를 다시 실행한다.
3. 이번 랭킹 초기화: `scripts/supabase_reset_rankings_20261105.sql`

세 번째 스크립트는 기존 랭킹과 소유 권한을 비공개 `ranking_reset_archive` 스키마에
백업하고 개수를 확인한 뒤 공개 랭킹을 비운다. 같은 스크립트를 다시 실행해도
초기화 후 새로 등록된 덱은 삭제하지 않는다. 기기의 로컬 덱은 삭제하지 않는다.
초기화 후 기존 연동은 다음 갱신에서 해제되며 덱 저장으로 비밀번호를 정해 재등록한다.
`0123`처럼 맨 앞의 0도 그대로 보존한다. 기존 긴 비밀번호로 저장된 덱은 기존 비밀번호로 계속 가져올 수 있다.
비밀번호는 bcrypt 해시, 기기 수정 토큰은 SHA-256 해시로만 보관하고 공개 테이블과 분리한다.

2026-11-06 사용자가 운영 SQL 적용을 완료한 뒤 공개 API와 배포 화면으로 확인했다.
숫자 4자리 검증·21명 입력 검증·권한 없는 수정/삭제 거절·비밀번호 테이블 접근 차단을 확인했고,
공개 랭킹은 0건이었다. 운영 DB에 테스트 덱을 등록하거나 비공개 백업 내용을 읽지는 않았다.
실제 저장/복원 왕복과 초기화 백업은 로컬 PostgreSQL(PGlite)에서 검증했다.

동일 이름 갱신은 위 확인 이후 추가한 변경이다. 현재 비밀번호 SQL 전체를 한 번 더 적용해야 한다.
새 클라이언트는 `save_ranking_password`를 사용하므로 적용 전에는 기기에 저장한 뒤
서버 설정 필요 메시지를 표시한다. 옛 등록 함수로 우회하여 중복을 만들지 않는다.
다른 이름으로 바꾸다가 기존 이름과 겹치는 경우에도 서버가 거절한다.
이미 중복 이름이 있는 DB에서는 SQL이 `duplicate_ranking_names`로 중단되며 기존 글은 보존한다.
이름 중복이 없는 상태에서 적용하며, 이번 변경을 위해 랭킹 초기화를 다시 실행하지 않는다.

## 라인업 보기

기본 화면은 일러스트이며 상단의 표 보기 버튼으로 한 장 요약표로 전환한다.
두 보기는 같은 선수 데이터와 계산 엔진 결과를 사용한다. 표에서 선수명을 누르면
기존 상세 편집창이 열린다. 표 아래의 접힌 설정에서 불펜 배치·전술·팀 버프·덱코를
수정할 수 있다. 새로고침하면 일러스트로 시작하며 저장된 덱 데이터는 유지된다.
표와 설정 영역은 본문 너비를 사용한다. 960px 이상 화면에서는 선수명·능력치를 16~18px,
점수를 18~20px로 표시하며 행 높이도 늘린다. 640px 이하 모바일 표 크기는 유지한다.

## 입력 검증과 복구 (v0.8)

덱 파일과 기기 저장 데이터는 스탯 배열·스킬 배열·버프·덱코·전술 값의 형식을 검사한다.
이전 덱에서 생략한 입력칸이나 길이가 짧은 스탯/스킬 배열은 빈칸으로 보완한다.
묶음 파일의 잘못된 항목은 제외하되 정상 덱은 읽는다.
기기 저장본에 잘못된 항목이 있으면 `rivals-decks-recovery-v1`에 원본을 보존한 후
정상 덱만 복원한다. 백업 실패 시 기존 저장본을 덮어쓰지 않는다.
화면에서 원본을 내려받거나 확인 후 백업을 삭제할 수 있다.
표의 계산 경고를 펼치면 모바일에서도 사유와 선수 편집 버튼에 접근할 수 있다.

## 덱랭킹 화면

공개 상위 50개 목록을 총점순으로 표시한다. 덱 이름을 선택하면 해당 행 아래에
라인업 보기·현재 덱과 비교·비밀번호로 가져오기와 관리 중인 글의 삭제가 펼쳐진다.
기기 안의 덱을 따로 나열하던 내 덱 랭킹은 제거했다. 기기 덱은 상단 선택 상자에서
고르고, 선수별 점수·덱코 합계는 라인업의 접힌 상세 보기에서 확인한다.
링크 공유/코드 가져오기는 랭킹 상단의 링크 공유 창에서 제공한다.
공유 URL은 랭킹 탭과 가져오기 창을 바로 열며, 가져오기 성공 후 라인업으로 이동한다.
공유 창을 닫으면 URL의 공유 코드를 제거해 탭 재진입 시 같은 창이 반복해서 열리지 않게 한다.
공개 랭킹 표시·소유 권한·같은 이름 갱신의 서버 규칙은 그대로 사용한다.

## 상단 덱 도구

이름 변경은 덱 저장 창에서 한다. 랭킹 탭에서는 중복 상단 저장 버튼을 숨기고
랭킹 영역의 현재 덱 등록·갱신 버튼을 사용한다.
백업/파일 불러오기/로컬 삭제는 덱 도구를 펼쳐서 선택한다.
파일 선택 하나로 JSON 백업과 xlsx/xlsm/xls를 읽는다.
현재 덱 하나와 전체 덱의 백업 결과가 같으면 전체 백업 버튼을 표시하지 않는다.
미저장 초안이 선택된 상태에서도 나머지 저장된 덱 전체를 백업할 수 있다.
마지막 로컬 덱을 삭제하면 새 ID의 빈 초안으로 전환하며, 공개 랭킹을 수정하거나 삭제하지 않는다.
기존 랭킹 관리 권한은 보존해 랭킹 메뉴에서 다시 관리할 수 있다.
