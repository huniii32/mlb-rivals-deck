# 이벤트 페이지 데모

위치: 시뮬레이터 → 이벤트(데모). 독립 개발 미리보기는 `/demo/events.html`.
현재 실제 참가·운영 데이터와 연결하지 않는다. 개인용 프로그램과도 무관하다.

## 확정된 사용자 요구
- 덱 등록이 이벤트 참여의 선행 조건.
- 스킬 점수 대회는 5회, 각 회차 스킬 3개 합계 중 최고 점수로 순위 결정. 점수 1등 커피 기프티콘 1개 + 응모권 추첨 1개, 총 2개. 점수 1등은 추첨 경품을 중복 수령할 수 없음.
- 덱 등록, 스킬 시뮬레이터, 슈프림 모먼트 조합, 일반 HOF 영입의 참여 이력을 확인하고 각각 1장씩 발급(현재 4종, 최대 4장).
- 이벤트 페이지에서 발급·참여 이력을 확인하고 컴퓨터로 응모권 추첨.

## 데모 구현/가정
- 등록은 데모 이름 입력으로 대체. 실 덱·랭킹·시뮬레이터 저장소 및 Supabase를 읽거나 변경하지 않음.
- 최고급 변경권 / 시그니처 선발 투수 / S 레벨 고정 / 잠금 없이 3슬롯으로 모든 참가자 조건 고정. 기존 확률 엔진과 랭킹대전 S0 점수 엔진을 사용하고 조건부 스킬은 시뮬레이터 기본 조건 사용. 사용자 수정 점수표 제외.
- 데모의 스킬 대회 1회 도전이 스킬 시뮬레이터 참여 이력이 됨. 조합·HOF는 이벤트 안의 1회 체험 버튼에서 기존 엔진으로 추첨하고 참여 기록을 남김. 응모권은 별도 참여 버튼을 눌러 받음.
- 예시 참가자 3명, 예시 응모권 9장. 실제 사용자 아님. 최고 점수가 같은 경우 공동 1위 중 한 명 추첨은 데모 임시 규칙.
- 추첨은 점수 1등에게 지급하는 1개와 별도로, 다른 참가자 한 명에게 커피 기프티콘 1개를 지급. 먼저 점수 1등을 확정한 뒤 참가자 ID를 기준으로 해당 참가자의 응모권을 전부 제외하고 나머지 응모권에서 한 장 추첨. 제외된 응모권도 참여/발급 기록은 보존하고 운영자 화면에 사유를 표시. 남은 대상이 없으면 추첨하지 않음. 추첨 대상의 각 응모권은 같은 확률. 따라서 보유 응모권 수에 비례해 당첨 가능성이 증가.
- 운영자 화면 미리보기에서 마감 후 도전/발급을 멈추고 대상 응모권을 고정. 한 번 추첨한 결과는 재추첨 불가. 새로고침 후에도 데모 결과 유지. 명시적 데모 초기화는 가능.
- 로컬 키 `rivals-event-demo-v2`만 사용. 브라우저 저장소는 사용자가 변경할 수 있어 실제 경품 지급의 근거로 사용하면 안 됨.

## 실운영 전에 필요한 별도 구현
참가자 식별 및 덱 소유권 확인, 서버의 원자적 5회 제한, 서버 확률 추첨/점수 산정, 시뮬레이터 참여 증거 발급 및 검증, 참가자·이벤트·항목별 응모권 고유 제약, 서버 마감·추첨·감사 기록, 운영자 인증, 일정·동점 규칙 확정 및 동일 인물 중복 수령 방지. 현재 4자리 덱 비밀번호만으로 한 사람이 여러 덱으로 참여하는 것을 차단할 수는 없다.

## 검증
`node --import tsx scripts/verify-event-demo.ts`
브라우저: 등록 전 제한, 5회 제한, 4장 중복 방지, 마감/추첨 후 잠금, 새로고침 복원, 모바일 320/390px, 원래 덱 유지, 원격 쓰기 없음.

조건 변경 시 이전 타자 데모 점수와 혼합하지 않도록 v2 키로 새로 시작한다. v1 기록은 덮어쓰거나 삭제하지 않는다. 투수 보직은 우선 선발(SP)로 설정했으며 전원 같은 조건이다.
