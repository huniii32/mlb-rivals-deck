# 라이벌 시리즈 월별 19/4/5 조합 추천

기록일: 2026-11-19 (한국 시간). 별도 개발 데모를 구현했다. 제공된 게임 화면을 반영한 버프 판정을 구현했다. 선발/중계/마무리 및 타자 후보 편성 규칙도 사용자 확인을 반영했다. 공지 자동 반영·운영 배포는 아직 진행하지 않았다.

## 사용자 요구

라이벌 시리즈에서 매달 19/4/5 버프를 맞추기 위해 선수 구성을 연구하는 수고를 줄인다. 월별 업데이트 공지를 반영해 해당 조건을 만족하는 여러 라인업을 보여준다. 단일 추천 덱이나 일반적인 스킬 코칭보다 **월별 조건 변화에 대응하는 조합 탐색**이 핵심이다.

`19/4/5`의 의미는 2026-11-19 사용자 답변으로 확정했다: **전체 OVR +19 · 타자 OVR +4 · 투수 OVR +5**. 세 버프 합계를 함께 만족하는 라인업이 목표이며, 선수 인원수를 뜻하지 않는다. 결과 화면에도 세 항목을 각각 표시한다. 정확히 목표와 일치하는 조합과 목표를 초과하는 조합은 구분해 표시하도록 설계한다.

## 기본 동작

1. 적용할 월/업데이트 버전과 희망 구단을 선택한다.
2. 보유 카드만 사용, 반드시 포함할 선수, 제외할 선수 등 선택 조건을 지정한다.
3. 해당 버전의 선수·카드·버프 규칙으로 목표 조건을 만족하는 라인업을 탐색한다.
4. 서로 다른 선수 구성의 조합을 여러 개 제시한다. 선수 순서만 바뀐 결과는 별도 조합으로 중복 표시하지 않는다.
5. 각 결과에 버프 합계·달성 근거·편성 위치·필요 선수·현재 덱 대비 교체 목록을 표시한다.
6. 조합을 저장하거나 공유하고, 다음 업데이트 때 달성 여부와 교체할 선수를 다시 확인한다.

## 추천 결과의 종류

| 결과 | 선택 기준 |
| --- | --- |
| 목표 버프 달성 조합 | 모든 필수 조건을 만족하는지 우선 검증 |
| 기존 덱 유지 조합 | 현재 라인업에서 바꾸는 선수 수가 적은 순서 |
| 보유 카드 우선 조합 | 보유 선수만 사용하거나 미보유 카드가 적은 순서. 두 모드를 명확히 구분 |
| 능력치 우선 조합 | 확인된 라이벌 시리즈 전용 산정 기준으로 비교. 다른 모드의 스킬 점수를 그대로 사용하지 않음 |
| 고정 선수 유지 조합 | 사용자가 지정한 선수를 포함해 나머지 자리를 탐색 |

서로 다른 조합이 충분히 존재할 때 여러 개를 제시한다. 결과가 없으면 달성했다고 표시하지 않고 부족한 조건과 탐색 범위를 설명한다. 시간 제한으로 탐색을 중단했다면 ‘조합이 없음’과 구분한다. 전체 최적해를 검증하지 못한 결과를 절대적인 최고 덱으로 표현하지 않는다.

## 월별 공지 반영과 기준 데이터

공지 한 건이 전체 선수·카드·포지션 정보를 제공한다고 가정하지 않는다. **검증된 기존 목록 + 공식 공지의 변경분 + 부족한 게임 화면 자료**로 해당 버전의 자료를 구성한다.

- 공지에서 실제 제공하는 항목을 먼저 조사한다. 구단·포지션·라이브 상태·라이벌 Pick·등급·능력치 중 무엇이 변경되는지 출처별로 확인한다.
- 선수는 이름만으로 합치지 않고 선수/카드 ID, 구단, 연도, 카드 종류 등으로 식별한다.
- 적용월 외에 공지 URL·게시/수정 시각·게임 적용일·출처 해시를 기록한다. 같은 달의 여러 업데이트를 덮어쓰지 않고 버전으로 구분한다.
- 자동 수집 → 변경점 추출 → 누락/충돌 검사 → 검수 → 기준 버전 확정 → 조합 재계산 순서로 처리한다.
- 첫 버전은 운영자 검수 후 공개한다. 이후 자동 반영 범위는 데이터 정확도 검증 결과에 따라 정한다.
- 이전 월의 선수 자료·버프 규칙·추천 결과를 유지해 기존 덱이 왜 조건을 잃었는지 설명한다.
- 자료가 불완전하면 이전 버전과 수집 중 상태를 구분한다. 오래된 자료를 이번 달 최신 조합으로 표시하지 않는다.

이 계획은 지금 운영 서버에 크롤러·스케줄러를 설치하거나 월별 자동 공개를 시작한다는 뜻이 아니다.

## 규칙 확인 현황 (버프 수치는 아래 11/19 화면 반영 기록 참조)

- 확정된 목표인 전체 +19 / 타자 +4 / 투수 +5를 판정할 최신 버프 합산 규칙. 목표 일치와 초과 조합을 구분하는 표시 방식.
- 최신 팀 인원·라이브 선수·라이벌 Pick·카드 등급 버프의 문턱값과 효과.
- 단계별 버프가 누적되는지, 최상위 단계만 적용되는지, 서로 다른 구단 효과가 중첩되는지.
- 주전·투수·보관 선수 등 어떤 슬롯이 버프 인원 계산에 포함되는지.
- 슬롯별 편성 인원·포지션 적합성·동일 선수 중복 편성 제한.
- 라이벌 Pick 여부와 라이브 카드 등급 등이 어느 업데이트 버전에 종속되는지.
- 스킬 레벨·잠재력의 OVR 보정과 개인 육성값을 어떻게 비교할지. 값이 확인되지 않으면 조합 적합성만 먼저 제공.

버프 조건을 만족하는 라인업 탐색과 정확한 최종 OVR 순위는 별개 단계다. 선수 소속·유형·등급·포지션·Pick 여부와 버프 규칙이 확인되면 조합 탐색부터 구현할 수 있으며, 모든 스킬 설명 수집이나 AI 코칭 완성을 기다릴 필요는 없다.

## 구현 순서와 검증

1. 사용자가 실제 게임에서 19/4/5를 달성한 라인업 한 개와 버프 내역을 기준 사례로 확보한다.
2. 같은 버전의 카드 목록과 버프 표를 정리한다. 숫자 하나를 임의 추정해 달성 판정을 만들지 않는다.
3. 기준 사례를 재현하는 버프 판정기를 만든다. 경계 인원, 카드 교체, 중복 카드, 보관 슬롯 포함 여부를 검증한다.
4. 조건을 만족하는 여러 조합을 찾는 탐색기를 추가한다. 결과를 별도의 판정기로 다시 검증한다.
5. 카드 고정·제외·보유 조건·교체 수 우선 정렬을 연결한다.
6. 월별 공지 변경분을 적용했을 때 이전 조합의 유효성 변화와 새 조합을 비교한다.
7. 개발 브랜치에서 확인한 뒤 월별 공개 운영 절차를 정한다.

작은 가상 카드 목록의 완전 탐색 결과와 추천 탐색 결과를 대조한다. 불가능한 조건, 입력 누락, 같은 달 재업데이트, 이전 버전 재현, 같은 선수 순서만 다른 중복 결과도 확인한다.

## 11/19 사용자 제공 게임 화면 반영

출처: 사용자가 2026-11-19 대화에 첨부한 팀 인원·라이브 선수·라이벌 픽·평가 등급 화면 4장. 규칙 버전 `user-screenshots-20261119`. 공식 2024년 가이드의 누락된 라이브 20명 효과도 게임 화면으로 확인했다.

| 분류 | 인원 → 추가 효과 (단계별 누적) |
|---|---|
| 같은 구단, 구단별 독립 | 3 → 전체 +1, 6 → 타자 +1, 8 → 투수 +1 |
| Live | 2 → 전체 +2, 5 → 상자 +10%, 8 → 타자 +1, 11 → 투수 +1, 14 → 상자 +10%, 17 → 전체 +2, 20 → 전체 +2 |
| Rival Pick | 2 → 전체 +1, 5 → 타자 +1, 8 → 상자 +10%, 10 → 투수 +1, 13 → 전체 +1, 15 → 전체 +1 |
| S등급 | 6 → 투수 +2, 12 → 타자 +2, 20 → 전체 +2 |
| A등급 | 6 → 투수 +1, 12 → 타자 +1, 20 → 전체 +1 |

S와 A는 실제 등급별 인원을 따로 센다. S를 A 이상으로 중복 집계하지 않는다. 미확인 등급은 효과를 임의로 더하지 않고, 확인된 효과 합계와 미확인 표시만 제공한다. 목표와 정확히 같은 경우/초과/미달을 구별한다. 선수별 OVR에 이미 포함된 Pick 효과와 이 라인업 버프는 별개이며, 최종 개인 OVR을 계산하지 않는다.

사진의 Live 24, Pick 2, S21/A5는 구단을 제외하면 전체 +9 / 타자 +3 / 투수 +3 / 상자 +20%다. 화면 전체 +17에서 구단 기여 +8을 역산할 수 있다. 테스트의 구단 8개×3명 이상은 이 기여를 재현하는 예이며, 화면에 보이지 않은 실제 구단별 명단을 확인한 것은 아니다.

목표 구성 예: 26명 중 S20/A6, Pick15, Live20 이상, 8개 구단 각 3명 이상. 구단 +8, Live 전체 +6·타자 +1·투수 +1, Pick 전체 +3·타자 +1·투수 +1, S 전체 +2·타자 +2·투수 +2, A 투수 +1 → **19/4/5, 상자 +30%**.

탐색은 인원수만 높이던 방식에서 실제 버프 목표와의 차이를 우선하도록 변경했다. 같은 구단·해당 슬롯의 선수 교체로 S20/A6을 맞추고, 목표를 찾으면 같은 구단·등급 안에서 서로 다른 선수 조합도 제공한다. CP를 중계로 배치해야만 나왔던 과거 19/4/5 후보는 유효하지 않으므로 제공하지 않는다. 사용자가 확인한 포지션 제한을 적용한 후보만 제공한다.

검증: 스크린샷 17/3/3 재현, 목표 19/4/5 및 상자 확률, 모든 문턱 직전/도달/직후, 구단별 누적, S/A 별도 계산, A6→A5 투수 -1, Pick15→14 전체 -1, 미확인 등급 판정, 서로 다른 목표 후보 검증. 브라우저에서 버프 합계·항목별 활성/미달 내역·후보 전환·JSON 내 계산 결과를 확인한다.

### 이번 공지에서 19/4/5가 불가능한 이유와 유효한 대안

- 26인에서 같은 구단 3명 효과는 최대 8구단(전체 +8), Live 효과는 최대 전체 +6, 등급 효과는 최대 전체 +2다. 전체 +19에는 Pick 15명 효과 전체 +3까지 모두 필요하다.
- 8구단에서 3명씩 쓰면 24자리를 사용한다. 나머지 2자리를 다른 구단으로 써도 최대 10개 구단이므로, 구단당 1명인 Pick 타자는 최대 10명이다.
- 11/19 공지의 Pick 투수는 SP 0명, RP 1명(AZ), CP 29명. CP는 중계로 배치할 수 없고 최대 2명이므로 Pick 투수 최대 3명이다.
- Pick 합계 최대 13명으로 필요한 15명에 미달한다. 이 판정은 해당 공지의 포지션/구단별 Pick 명단 및 26인 편성 조건에 대한 상한 증명이며, 단순히 제한 탐색에 실패한 것을 불가능이라고 표시하는 것이 아니다.
- 위 상한과 목표에 가장 가까운 후보 탐색을 분리한다. 카드 조건 구성에서 마무리 2명일 때 **18/4/5**, 마무리 1명일 때 **17/4/5** 후보를 찾았다. 선수별 최종 OVR 최대화를 증명하는 기능은 아니다.
- 중계 역할 선택은 슬롯별로 보존하고 JSON에 함께 저장한다. 선발 수를 4↔6으로 바꿔도 투수 총원 12명과 타자 후보 5명은 유지한다. 마무리 3명, CP를 RP에 넣은 편성은 검증에서 거부한다.

최종 검증: `npm test`, TypeScript/일반 빌드, 독립 데모 빌드 통과. `node scripts/verify-rivals-series-browser.cjs`로 Web Worker 계산, 18/4/5 표시, 계산 내역, 후보 전환, SP4~6/CP1~2, 후보 타자 5명, 중계 7명 전원 롱릴리프 지정, JSON 내 편성/역할/버프 보존, 390/768/1366px 가로 넘침 없음을 확인했다.

## 일반 카드 자유 조합 (2026-11-19)

사용자 요청에 따라 Pick만 공식 선수 실명으로 표시하고, 일반 카드는 구단·S/A등급·라이브/시즌 종류·슬롯 포지션에 대한 필요 조건으로 표현한다. 특정 일반 선수나 존재 여부를 임의로 확정하지 않는다. 실명 명단에서 골랐던 일반 선수를 숨기는 것에 그치지 않고, 후보 개선 과정에 30개 구단×S/A의 조건 카드를 포함한다.

- 기본은 시즌 일반 카드 6명+라이브 20명. 검색 시 시즌 카드 수를 0~6명으로 선택할 수 있다. 버프 목표를 유지하려면 라이브 20명 이상이 필요하다.
- 결과에서 일반 카드의 구단·등급·종류를 자유롭게 수정하면 구단별 인원과 모든 버프가 즉시 갱신된다. 직접 시즌 카드를 7명 이상 넣는 것도 가능하며, 라이브 20명 미달과 버프 감소를 표시한다.
- Pick 선수의 이름·등급·포지션·라이브 여부는 공식 자료를 유지하며 일반 카드 편집으로 바꿀 수 없다. CP→RP 금지와 기존 편성 인원 조건도 유지한다.
- 일반 카드 조건에는 실명·연도·OVR을 만들어 넣지 않는다. 사용자가 실제 보유 카드에서 해당 조건과 포지션을 만족하고 이미 편성한 선수와 중복되지 않는 선수를 골라야 한다. 조건 카드의 존재/보유/실명 중복까지 확인한 라인업이라는 표시는 하지 않는다.
- JSON은 조건 카드 표시와 수정한 구단·등급·종류, 적용 버프 및 역할을 보존한다. 각 후보 수정은 다른 후보나 기준 데이터에 영향을 주지 않는다. 일반 조건이 같고 슬롯 번호만 바뀐 결과를 별도 조합으로 세지 않는다.
- 일반 카드의 팀·등급을 자유롭게 하더라도 현재 Pick의 구단별 인원/포지션 상한은 변하지 않는다. 이번 공지의 19/4/5 불가능 근거는 계속 유효하다. 시즌 카드를 6명 포함한 18/4/5 설계 후보를 제공한다.

검증: 여섯 투수 편성에서 조건 카드/시즌 6명/라이브 20명 유지, 라이브 20→19 시 전체 -2, S/A 변경, 원본·타 후보 불변, Pick 편집 금지, JSON 보존 및 브라우저 즉시 재계산을 확인한다.
