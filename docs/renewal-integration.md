# 덱관리 리뉴얼

루트 앱에 리뉴얼 UI를 연결한다. 초기 디자인 프로토타입은 저장소 밖에 보관하고 실제 앱 소스와 분리했다. 개인용 도감 수집 프로그램은 웹 배포에 포함하지 않는다.

## 연결 범위

- 기존 App의 덱 저장소, 백업/엑셀 가져오기, 비밀번호 등록·복원, 소유 세션과 자동 랭킹 갱신을 그대로 사용한다.
- 선수 편집과 덱스코어·팀 버프·불펜 전술은 `applyDeckUpdate`와 기존 계산 엔진을 사용한다. 직접 입력한 최종 능력치에도 육성 변경분이 반영된다.
- 일러스트 기본 보기, 타자 경기장 배치, 선발·불펜 카드와 모든 점수 열이 표시되는 반응형 표를 제공한다.
- 타자 카드의 이름·등급 영역을 포함한 세로 공간을 확보해 1B–DH와 CF–내야 카드 겹침을 방지한다. 불펜 일러스트는 승리조/추격조/롱릴리프/마무리를 각각 한 줄로 표시하고 빈 등록 슬롯도 해당 역할에 둔다.
- 1024px 이상에서는 제목과 덱 도구를 한 줄에 배치하고 여백을 줄인다. 경기장과 카드는 컨테이너 너비와 화면 높이에 따라 크기를 조정하며 경기장 높이는 420~620px로 제한한다. 모바일 스타일은 그대로 유지한다.
- 스킬 비교는 모든 슬롯이 빈 상태(합계 0점)로 시작한다. 슬롯별 S~S4와 조건, 기타 등급/사용자 스킬, 3·4슬롯을 지원하며 사용자 점수 수정도 반영한다.
- 공개 랭킹 상단에는 현재 선택한 덱의 전체 순위를 표시하고, 아래에는 1위부터 목록을 표시한다. 내 순위는 인증된 랭킹 연결로 확인하며 상위 5개/검색 범위와 무관하게 유지한다. 전체 목록은 500개 단위로 모두 읽으며 검색 후에도 원래 순위를 표시한다.
- 기존 세 시뮬레이터, 점수 가이드, 공지, 문의, 정보글을 유지한다. 이벤트의 월요일 00시 KST 잠금 규칙도 유지한다.

## 데이터 범위

Cloudflare 브랜치 미리보기는 운영 주소와 브라우저 저장소가 분리되어 있다. 기존 덱을 사용하려면 백업 파일이나 랭킹의 비밀번호 가져오기를 이용한다. **미리보기의 공개 랭킹은 동일한 Supabase에 연결되므로, 가져온 덱을 편집하면 실제 랭킹에도 반영된다.** 미리보기에서만 화면 상단에 실제 연동임을 표시한다. 운영 빌드에서는 해당 안내와 빈 공간을 제거한다.

## 검증

```sh
npm test
npm run test:db
npm run build:cloudflare
# Playwright와 Chromium이 설치된 검증 환경. 앱은 별도로 실행한다.
RENEWAL_URL=http://localhost:5176 node scripts/verify-renewal-browser.cjs
```

브라우저 검증은 REST와 실시간 연결을 가로채 운영 DB를 수정하지 않는다. 21명 덱의 비밀번호 오류/복원, 입력 필드 보존, 강화·훈련 및 수동 최종값 보정, 같은 랭킹의 소유 세션 갱신, 새로고침 후 유지, 덱스코어·팀 버프·전술, 320~1920px 표, 스킬별 레벨/조건/4슬롯, 세 시뮬레이터 실행, 이벤트 잠금, 로고 이동, 기기 저장/백업/파일 가져오기/4자리 PIN 등록을 확인한다.

실제 소유 덱의 비밀번호 인증·수정은 사용자 인증이 필요하다. 자동 검증은 모의 응답과 로컬 DB 테스트로 수행하며, 배포 후 공개 랭킹 조회는 별도로 확인한다.

## 소스 구성

- `src/components/renewal/`: 라인업, 편집, 스킬 비교, 공통 화면 구성.
- `src/components/renewal/styles/`: 레이아웃, 라인업, 선수 편집, 스킬 입력·비교, 기존 기능 연결 스타일. PC 밀도 조정은 마지막에 불러오는 `desktop.css`에 모으며 `renewal.css`의 import 순서를 유지한다.
- `src/lib/deckScoreTargets.ts`: 연도 입력행, 대상 선택 및 설명. `deckScoreOptions.ts`: 설정/읽기 전용 미리보기가 함께 사용하는 선택지.
- 사용하지 않는 이전 `PlayerEditor.tsx`, `LineupTable.tsx`와 표 전용 CSS는 제거했다. `LineupView.tsx`는 덱 보기·비교에서 계속 사용한다.
- 기존 저장소 키, JSON 형식, 랭킹 RPC와 DB 구조는 유지한다.

## 배포

`main` 병합 후 Cloudflare Pages와 기존 GitHub Pages가 자동 배포된다. Cloudflare의 `CF_PAGES_BRANCH`를 읽어 브랜치 미리보기만 안내띠를 표시한다. 로컬 개발 화면에도 안내띠가 표시된다.
운영 빌드 검증: `npm run build:cloudflare` 후 preview 서버에서 `RENEWAL_EXPECT_PREVIEW=0`으로 브라우저 검증을 실행한다.
