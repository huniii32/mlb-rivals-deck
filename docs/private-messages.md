# 운영자 개인 쪽지 / 기프티콘 이미지

2026-11-19 개발 브랜치 구현. 같은 날 사용자 요청으로 운영 배포를 진행한다. 실제 쪽지 발송은 운영자가 수신자와 내용을 확인한 후 수행한다.

## 사용자 흐름

- 운영자는 기존 `/event-control/`의 관리자 로그인 후 **개인 쪽지 보내기**에서 등록 덱을 검색한다. 이벤트 당첨 여부는 이름이 아닌 이벤트 참가 기록의 `ranking_id`로 표시한다.
- 제목·본문과 이미지 한 장을 작성하고 **전송 내용 확인 → 이 덱에 쪽지 보내기**를 누른다. 인증 요청 안내문만 보낼 수도 있다.
- 사용자는 덱랭킹에서 기존 비밀번호로 자기 덱을 가져온 후 상단 **쪽지함**에서 덱을 선택한다. 운영자에게 답장하거나 다른 사용자에게 발송하는 기능은 없다.
- PNG/JPG/WEBP, 최대 2MiB. 원본 바이트를 유지해 바코드 해상도를 변경하지 않는다. 쪽지 안에서 표시하고 **이미지 저장**으로 다운로드할 수 있다.
- 운영자는 보낸 내역·최초 읽은 시각을 확인한다. 운영자의 미리보기는 수신자 읽음으로 계산하지 않는다.
- 별도 게임 덱 인증은 요구하지 않는다. 당첨 덱 쪽지함으로 경품을 발송한 후 운영자가 이벤트 관리에서 지급 완료를 기록한다. 이미지 발송·읽음이 경품 사용을 뜻하지 않으며 지급 상태를 자동 변경하지 않는다.
- 사이트 내 쪽지함이며 외부 커뮤니티 쪽지·이메일·푸시 알림을 보내지 않는다. 당첨 공지에서 쪽지함 확인을 안내해야 한다.

## 접근과 보관

`deck_private_messages`는 RLS를 켜고 익명/일반 인증 역할의 테이블 직접 접근을 모두 차단한다. 기존 운영자 세션을 매 요청 검증한 RPC만 발송·발송 내역 열람이 가능하다. 수신자는 `ranking_password_sessions`의 덱 ID/토큰 조합이 맞아야 목록과 본문·이미지를 읽을 수 있다. 덱 이름·메시지 UUID만으로는 접근할 수 없다.

이미지는 공개 Storage 버킷이나 영구 URL 없이 비공개 테이블의 `bytea`로 저장한다. 인증된 POST RPC가 본문/이미지를 반환하고 브라우저에서 임시 Blob URL을 생성한다. 쪽지 목록에는 이미지 바이트와 본문을 넣지 않는다. 이미지는 로컬/세션 스토리지에 저장하지 않으며 화면을 닫거나 덱을 변경하면 Blob URL을 폐기한다. 사용자가 직접 저장한 이미지와 이미 내려받은 자료를 원격 회수할 수는 없다.

기존 덱 인증 방식을 재사용한다. 덱 비밀번호와 인증 토큰이 포함된 덱 백업 파일을 가진 사람은 쪽지를 볼 수 있으므로 백업 안내에 쪽지 열람 권한도 명시한다. 실제 게임 계정 소유 확인 기능이나 이메일 인증 기능을 새로 추가하지 않는다.

관리자가 확인한 발송 요청은 UUID로 중복을 막는다. 네트워크 응답이 끊긴 경우 같은 확인 화면에서 재시도하면 기존 결과를 반환한다. 같은 UUID로 수신자·내용·이미지를 바꾼 요청은 거절한다. 화면을 떠나 요청을 잃었다면 보낸 내역을 먼저 확인한다.

현재 메시지는 등록 덱 삭제 시 함께 삭제된다. 별도의 삭제/회수/자동 보존기간 기능은 없다. 소규모 이미지 발송용이며 운영량이 늘면 별도 비공개 저장소와 보존기간 정책을 고려한다.

## 배포 준비

기존 DB에는 `scripts/supabase_mig_private_messages.sql`만 추가 적용한다. 선행 설치는 `supabase_mig_deck_passwords.sql`, `supabase_mig_events.sql`, `supabase_mig_event_operator.sql`이다. 기존 데이터는 변경하지 않는다. 재실행해도 메시지가 유지된다. 새 설치용 `build-event-setup.cjs`에도 포함한다.

DB 마이그레이션 적용 후 프런트를 배포한다. 함수가 없으면 쪽지함에 연결 준비 안내를 표시하고 전송하지 않는다. 서비스 역할 키를 브라우저에 추가할 필요가 없고 기존 관리자 비밀번호도 그대로 사용한다.

현재 브랜치 미리보기는 `VITE_DEVELOPMENT_SANDBOX=1`로 운영 DB 연결이 비활성화되어 있어 실제 관리자/수신자 쪽지는 조회할 수 없다. 동작 시험은 아래 로컬 DB에서 진행한다.

## 검증

```sh
node scripts/verify-private-messages.cjs
# 별도 터미널: 실제 DB와 분리된 가상 사용자/가상 경품
EVENT_PILOT_PORT=8794 EVENT_PILOT_WEB_PORT=5194 EVENT_PILOT_DIR=/tmp/rivals-private-messages-pilot node scripts/event-pilot-server.cjs
node scripts/verify-private-messages-browser.cjs
```

SQL 검증: 운영자 외 발송 거부, 타 덱 열람 차단, 본문/이미지 테이블 직접 접근 차단, 위조·과대 이미지 거부, 중복 발송 방지, 최초 읽음 기록, 관리자 열람 구분, 당첨 덱 ID 연결, 페이지 구분, 마이그레이션 재실행, 인증 철회·로그아웃·만료.

브라우저 검증: 실제 로컬 SQL을 통한 이미지 첨부·확인·전송, 응답 유실 후 재시도, 이미지 원본 다운로드, HTML 문자 안전 표시, 브라우저 저장소에 메시지 미보관, 새로고침, 응답 대기 중 덱 전환 시 이전 쪽지 미노출, 읽음 확인, 로그아웃, PC/320px/390px.

## 새 쪽지 알림

비밀번호로 인증된 현재 선택 덱에 대해 앱 진입 시, 화면 복귀 시와 접속 중 30초마다 목록을 확인한다. 읽지 않은 새 쪽지는 화면 하단 알림으로 표시하고 ‘쪽지 확인’으로 해당 덱의 쪽지함을 연다. 선수 편집·다른 대화상자 사용 중에는 확인을 잠시 멈춘다. 사이트가 닫혀 있을 때의 브라우저 푸시 알림은 아니다.

알림 자체는 서버 읽음 처리를 하지 않는다. 같은 브라우저에서 반복 표시하지 않도록 수신 덱별 알림 표시 이력에 메시지 ID만 최대 1,000개 보관한다. 제목·본문·이미지·인증값은 이 이력에 저장하지 않는다. 다른 기기에서는 읽지 않은 쪽지를 다시 알릴 수 있다. 덱/인증 변경은 컴포넌트를 다시 만들고 이전 요청 결과를 버리며, 인증 오류 시 알림을 제거한다.

알림 브라우저 검증: `EVENT_PILOT_PORT=8795 EVENT_PILOT_WEB_PORT=5195 EVENT_PILOT_DIR=/tmp/inbox-alerts-pilot node scripts/event-pilot-server.cjs` 실행 후 `node scripts/verify-inbox-notifications-browser.cjs`. 본인 덱만 알림, 읽음 상태 보존, 닫기/새로고침 중복 방지, 새 쪽지 감지, 쪽지함 이동, 이전 덱 응답이 늦게 도착하는 상황과 320/390/1366px을 확인한다.

## 당첨자 발송 화면

운영자 주소는 기존 `/event-control/`을 유지하며 일반 사이트에는 진입 링크를 추가하지 않는다. 관리자 로그인 후 ‘개인 쪽지 보내기’ 상단에서 점수 1위와 추첨 당첨자를 선택하거나, 이벤트 관리의 당첨자 카드에서 ‘쪽지 보내기’를 누르면 해당 덱이 자동 선택된다.

수신자는 기존 운영자 RPC의 당첨 구분으로 조회한다. 이는 참가 기록의 ranking_id와 현재 등록 덱을 연결하므로 이름 변경에도 대응하며, 같은 이름의 다른 덱으로 대체하지 않는다. 첫 50명 밖의 당첨자는 다음 페이지를 조회한다. 삭제된 덱은 선택 불가로 안내한다. 추가 DB 마이그레이션은 없다.

‘받는 덱 선택’은 서버의 50개 단위 페이지를 끝까지 자동 조회해 전체 등록 덱을 표시한다. 검색 결과도 50개를 초과하면 모두 조회하며, 건수 표시와 ‘전체 덱 보기’를 제공한다. 검색창과 버튼은 같은 높이로 정렬한다. `scripts/verify-recipient-list-browser.cjs`는 로컬 파일럿에 123개의 가상 조회 결과를 적용해 전체 목록, 여러 페이지 검색, 선택 유지, 검색 초기화 및 320/390/1366px 정렬을 확인한다.

당첨 안내문/기프티콘 전달문 양식, PNG·JPG·WEBP 첨부와 발송 전 확인, 보낸 내역과 읽음 확인을 제공한다. 내용 작성부터 수신 덱을 고정하며 ‘다시 편집’에서도 고정을 유지한다. 다른 덱을 선택하려면 작성 취소 또는 발송을 완료한다. 경품 지급 완료 기록은 기존 이벤트 관리에서 별도로 처리한다. 자동 발송하거나 지급 완료로 자동 변경하지 않는다.

2026-11-19부터 게임 덱 인증 없이 당첨 덱 쪽지함으로 직접 지급한다. 기존 설치에서 지급 완료 기록의 인증 선행 조건을 해제하려면 `supabase_mig_event_direct_delivery.sql`을 적용한다. 인증 완료로 자동 기록하는 우회 처리는 하지 않는다.

검증: `scripts/verify-prize-recipients.ts`는 페이지 탐색·이름 변경·삭제·인증 오류를, `scripts/verify-winner-messages-browser.cjs`는 8796/5196 로컬 SQL 파일럿에서 실제 당첨자 선정→수신 덱 자동 선택→이미지 확인/발송→본인 열람·읽음 및 모바일 UI를 검사한다. 운영 당첨자에게 테스트 쪽지를 보내지 않는다.
